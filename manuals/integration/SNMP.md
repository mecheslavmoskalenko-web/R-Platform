# Интеграция по SNMP — рабочий конспект

> Источник: выгрузка `SNMP.pdf` из руководства администратора R-PLATFORMA (4 стр.).
> Сам PDF — в этой же папке.

## Назначение

Драйвер опрашивает сетевые устройства (маршрутизаторы, ПК, принтеры и т.д.)
по стандартному протоколу SNMP.

## Порядок настройки

1. **Создать экземпляр ИС** на вкладке «ИС»: тип ИС — SNMP, включить «Автозапуск»,
   загрузить шаблон настроек. Единственное свойство — `configFilePath`, путь к JSON-файлу
   конфигурации.
2. **Запустить драйвер.**
3. **Загрузить данные типа ИС** на вкладке «Типы ИС» — поочерёдно запросить
   команды, события и типы оборудования, проставить соответствие локальным,
   перезапустить ИС.
4. **Загрузить конфигурацию ИС** — запросить конфигурацию оборудования из ИС,
   в режиме редактирования проставить устройствам режим «Норма», перезапустить ИС.

Актуальное описание настроек лежит рядом с драйвером: `./proc/drv/snmp/`

## Структура конфигурационного файла

JSON-массив объектов-устройств. Поля верхнего уровня:

| Поле | Назначение |
|---|---|
| `mac` | уникальный идентификатор оборудования (GUID) |
| `name` / `note` | наименование и описание |
| `is_equip_type_guid` | тип оборудования ИС — только `SNMP_DEVICE` |
| `equip_type_varnam` | varnam типа оборудования в R-PLATFORMA |
| `options` | параметры подключения и опроса |
| `mibs` | массив опрашиваемых параметров |
| `triggers` | реакции на изменение параметров |

### options

`target` (адрес), `community`, `version` (`v1` / `v2c`), `transport` (`udp4` / `udp6`),
`port`, `trap_port`, `interval` (интервал опроса), `timeout`, `retries`.

### mibs

`type` — `variable` или `trap`; `id` — числовой идентификатор параметра;
`oid` — SNMP OID; `interval_factor` — множитель к `options.interval`;
`action` — `leaf_value`, `leaf_delta`, `tree_summ`, `tree_average`, `tree_array`.

### triggers

`expression` — выражение расчёта; `condition` — условие; `event_varnam` — varnam
генерируемого события; `event_description` — описание; `compl_fl` — флаг
комплементарности (парные события «возникло / снято»: `1` и `-1`).

Событие генерируется, когда результат `expression` удовлетворяет `condition`.
В обеих строках допустима макроподстановка `#id.attr#`, где `attr` — `value`
(значение согласно `action`) или `interval` (`interval_factor × interval`).

## Ограничения текущей версии

- SNMP trap'ы не используются (`trap_port` и `type: trap` зарезервированы) —
  только опрос (polling). Существенно для расчёта времени реакции: целевые 2,5–3 сек
  по ТЗ ограничены снизу интервалом опроса.
- Единственный тип оборудования — `SNMP_DEVICE`.
- Конфигурация задаётся файлом на ФС сервера, не через UI — попадает
  под требования к резервному копированию бинарных файлов сервера.
