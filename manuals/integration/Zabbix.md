# Интеграция с Zabbix — рабочий конспект

> Источник: выгрузка `zabbix.pdf` из руководства администратора R-PLATFORMA (5 стр.).
> Сам PDF — в этой же папке.

**Требуется R-PLATFORMA версии 3.6 или выше.**

## Назначение

- Получение списка оборудования (hosts) и каналов (items, триггеры, интерфейсы).
- Генерация событий R-PLATFORMA при достижении заданных значений.

## Порядок настройки

1. **Создать экземпляр ИС** на вкладке «ИС»: тип ИС — Zabbix, включить «Автозапуск»,
   загрузить шаблон настроек и актуализировать значения.
2. **Запустить драйвер.**
3. **Запросить конфигурацию** на панели «Конфигурация SCADA» → «Поиск оборудования»:
   запустить процесс, нажать «Запросить», отметить нужные hosts и items,
   сохранить конфигурацию в БД.
4. **Настроить оборудование и каналы**: в разделе «Оборудование» задать
   местоположение и режим работы, в разделе «Каналы» — триггеры для формирования
   событий.

⚠️ После любого изменения конфигурации оборудования или настроек каналов
процесс драйвера нужно перезапускать (кнопка «Перезапуск процессов» доступна
в разделах «Поиск оборудования», «Каналы» и «Оборудование»).

Актуальное описание настроек лежит рядом с драйвером: `./proc/drv/zabbix/`

## Настройки драйвера

**Подключение к Zabbix:** IP-адрес сервера, протокол передачи данных,
токен сервера, таймаут запроса.

**Блок SCADA:** интервал пересчёта каналов (мсек).

**Блок MQTT:** корневой маршрут сообщений, адрес и порт брокера,
имя пользователя и пароль, интервалы посылки канала и значения, интервал
поддержания связи, интервал переподключения, таймаут подключения.

## Токен доступа

Создаётся на стороне Zabbix: **Users → API tokens → Create API token**.
В документации показан Zabbix 7.2.6.

Токен и пароль MQTT — секреты. В репозиторий не коммитить.

## Заметки по архитектуре

Драйвер подтверждает наличие **MQTT** в стеке R-PLATFORMA — ранее в реконструкции
архитектуры фигурировал только RabbitMQ. Похоже, MQTT используется как
транспорт внутри SCADA-контура (общий блок настроек SCADA + MQTT встречается
в драйверах телеметрии). Требует проверки на стенде — важно для схемы
интеграции с ЕЦ МиР.

Модель данных общая для SCADA-драйверов: **Оборудование → Каналы → Триггеры → События**.
Та же схема у SNMP-драйвера, только там она задаётся JSON-файлом, а здесь
подтягивается из Zabbix через API.
