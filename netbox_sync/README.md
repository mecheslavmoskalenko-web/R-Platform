## Опорные факты

### Источник

БД `core`, PostgreSQL **11.22**, сборка `Debian 1:11.22-astra.se5.1+ci3` — Astra Linux SE 1.7. Бэкап `core_08_14_2026.backup` от 14.08.2026, формат custom.

Расширения: `pg_stat_statements`, `uuid-ossp`. **PostGIS отсутствует.**

Мандатный контроль включён на уровне БД (`MAC CCR ON`), но все метки `{0,0}`, все 741 таблица создана `WITH (MACS=FALSE)` — фактического разграничения нет.

### Локации

3 418 записей, из них 3 071 активная (`locdelmsk=1`), 347 удалённых.

Состав активных: 2 679 помещений, 202 этажа, 153 здания, 22 объекта, 7 функциональных групп, 2 корня.

**Координаты** — `jsoncoords`, формат:

```json
{"origin": {"x": 33.9396608, "y": 0, "z": 44.3962072}, "locked": true, "lockedByUser": 16567}
```

WGS84 с перестановкой осей: **`x` — долгота, `z` — широта**, `y` всегда 0. Заполнено у 3 001 записи. Диапазон: 33.934–34.049 в.д., 44.393–44.421 с.ш.

### Особенности данных

- `varnam` уникален у всех 3 071 записи, максимум 30 символов — годится в `slug` напрямую. Дефекты: «KNS»/«kns» схлопываются при lowercase, значение `locFloorBlockА0М` содержит кириллицу
- `locnam`, `locnot` — массивы по языкам, фактически используется один язык, элемент `[1]`
- Максимальная длина наименования ровно **100** символов при лимите NetBox 100 — впритык
- `parlocid integer NOT NULL`, корень обозначается **нулём**, не NULL
- `tagids`, `jsonprops`, `objectproptplid` — пусты у всех записей, механизмы не задействованы
- `loctimezone` = 0 у всех записей
- Внешних ключей на 742 таблицы всего 217; связи держатся на соглашении «поле `*id` со значением 0 = не задано»

## Принятые решения

**Целевая структура Р-Платформы утверждена заказчиком**, изменяется только по его решению.

| Уровень | Модель NetBox |
|---|---|
| `locRegion` — страна, республика, округ, город, село | `dcim.Region` (рекурсивная) |
| `locProvince` — объект / площадка | **`dcim.Site`** |
| `locBuilding` — здание, блок | `dcim.Location` (рекурсивная) |
| `locFasad`, `locFloor`, `locRoom` | `dcim.Location` |
| Функциональное назначение | `extras.Tag` |

Граница `Site` = площадка, обоснование: подсети нарезаны по подсистемам (СКУД, СОТ, ОПС) и сквозные по комплексу, к отдельному зданию их не привязать. Подсистемы разделяются ролью префикса `ipam.Role`.

**`dcim.SiteGroup` не используется** (решение от 19.08.2026). Площадок немного, группировка избыточна: география реализована через `Region`, функциональное назначение — через теги. Поле `Site.group` остаётся пустым. Резерв на будущее — тип площадки при росте их числа; для принадлежности эксплуатирующей организации точнее `Tenant`.

Серверные и коммутационные — обычные `Location` внутри площадки, отдельными сайтами не являются: своего адреса и ввода связи у них нет, а оборудование ИСБ размещено по всем помещениям, а не только в них.

**Р-Платформа остаётся стоковой** — изменения схемы БД и кода исключены, чтобы сохранить обновляемость. Внешний ключ NetBox реализуется штатным механизмом объектных свойств (`objectprops` с `uniquefl`, поиск через `s_find_by_jsonprops`).

## Полезные команды

Выгрузка локаций из бэкапа:

```
pg_restore -t locations -t locationtyps --no-owner --no-privileges \
  -f locations.txt core_<дата>.backup
```

Схема целиком, без данных:

```
pg_restore -s --no-owner --no-privileges -f schema.sql core_<дата>.backup
```

## Что сделано в тестовой сборке NetBox

Регионы заведены вручную 13.08.2026 — 10 записей, включая служебные узлы «Населённый пункт не определён» и «плато Ай-Петри».

Загружено: 5 площадок, 3 050 локаций, 1 стойка. Из выгрузки исключены все узлы с наименованием «Нулевая» и потомками — 9 записей.

**Особенность тестовой загрузки.** При импорте через форму NetBox родитель локации ищется по наименованию глобально, поэтому пришлось сделать все 3 050 наименований уникальными: `1 этаж` превратился в `1 этаж (Блок А)`, `1 этаж (Энергоцентр)` и так далее — уточнено 1 216 записей. Это протез под ограничение формы, а не проектное решение: при работе через REST API родитель передаётся по `id`, и наименования можно оставить как в платформе.
