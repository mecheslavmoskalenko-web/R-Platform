# `s_set_locations` — контракт функции

Восстановлено по телу функции из выгрузки схемы БД `core` от 14.08.2026. Официальной документацией не является, требует подтверждения у ООО «Рубеж».

```sql
s_set_locations(v_json_params jsonb) RETURNS text
```

---

## Что возвращает

**Закрывает открытый вопрос: `locid` возвращается.** В конце функции:

```sql
a_res := s_get_locations(('{"locid":'||a_locid::text||',"mode":"list"}')::jsonb);
return a_res;
```

То есть при создании возвращается **полная карточка созданной локации** в том же формате, что отдаёт `s_get_locations`, включая присвоенный `locid`. Двухфазная запись на этапе 2 реализуема: создали в платформе → получили `locid` → записали обратно в NetBox.

Режимы `upd_template`, `upd4map`, `packages_processing`, `packages_processing_upd4map`, `refresh_mat_views` возвращают `true` и карточку не отдают.

---

## Режимы (`mode`)

| Режим | Назначение |
|---|---|
| `add` | создание локации |
| `upd` | обновление, изменяются только переданные поля |
| `upd_tags` | обновление только тегов |
| `upd_template` | массовая привязка шаблона объектных свойств |
| `upd4map` | обновление только координат и данных модели |
| `packages_processing` | пакетная обработка массива `package[]`, каждый элемент как `upd` |
| `packages_processing_upd4map` | пакетное обновление координат |
| `del` | мягкое удаление |
| `refresh_mat_views` | пересчёт материализованных представлений тегов |

---

## Параметры

### Общие

| Ключ | Тип | Примечание |
|---|---|---|
| `mode` | text | обязательный |
| `langid` | int | индекс языка в массивах `locnam` / `locnot`, по умолчанию `1` |
| `sysuser` | — | передаётся в журнал аудита `s_set_history` |
| `refresh_tags` | bool | пересчитывать ли материализованные представления, по умолчанию `true` |

### Поля локации — режимы `add` и `upd`

| Ключ | Тип | Примечание |
|---|---|---|
| `locid` | int | обязателен для `upd`, игнорируется при `add` |
| `locnam` | text | пишется в `locnam[langid]` |
| `locnot` | text | пишется в `locnot[langid]` |
| `loctypid` | int | тип локации |
| `parlocid` | int | родитель, корень — `0` |
| `jsoncoords` | jsonb | передаётся объектом, не строкой |
| `jsonmodeldata` | jsonb | |
| `jsonprops` | jsonb | значения объектных свойств |
| `varnam` | text | см. предупреждение ниже |
| `loctimezone` | int | по умолчанию `0` |
| `objectproptplid` | int | шаблон объектных свойств, по умолчанию `0` |
| `tagids` | array | JSON-массив, внутри преобразуется в массив PostgreSQL |

В режиме `upd` переданными считаются только те ключи, которые присутствуют в объекте. Отсутствующий ключ оставляет прежнее значение — частичное обновление поддерживается штатно.

### `upd_template`

| Ключ | Значения |
|---|---|
| `locids_mode` | `empty` — все локации без шаблона · `all` — все · `ids` — перечисленные в `arr_locid` |
| `arr_locid` | массив `locid` |
| `objectproptplid` | привязываемый шаблон |

### `del`

Принимает `locid` и/или `arr_locid`. Удаление мягкое.

```json
{
  "mode": "add",
  "langid": 1,
  "locnam": "Серверная (03.21)",
  "locnot": "",
  "loctypid": 5,
  "parlocid": 292,
  "varnam": "servernaya-03-21",
  "jsoncoords": {"origin": {"x": 33.9396608, "y": 0, "z": 44.3962072}},
  "tagids": [3, 7],
  "loctimezone": 0,
  "refresh_tags": false
}
```

## Предупреждения по итогам разбора

### `varnam` передавать всегда явно

Если ключ не передан, платформа генерирует значение сама:

```sql
case when (v_json_params->'varnam') is null
     then 'locations_'||(currval('sq_locations'))::text
     else (v_json_params->>'varnam') end
```

Получится `locations_1706` вместо осмысленного идентификатора. Поскольку `varnam` используется как источник `slug`, его необходимо передавать при каждом создании.

### Массовая загрузка — обязательно `refresh_tags: false`

При каждом вызове с `refresh_tags: true` (значение по умолчанию) выполняется `s_tagutils_refresh_mat_views(4)` — пересчёт шести материализованных представлений тегов. На загрузке трёх тысяч локаций это три тысячи полных пересчётов.

Правильный порядок для массовой загрузки:

1. все вызовы с `"refresh_tags": false`
2. один завершающий вызов `{"mode": "refresh_mat_views"}`

Сама платформа в пакетном режиме поступает именно так — в коде есть комментарий разработчика об этом.

### Пакетный режим не создаёт записи

`packages_processing` обрабатывает каждый элемент массива `package[]` **как `upd`**, принудительно подставляя `"mode": "upd"`. Массовое создание пакетом не поддерживается: 3 050 локаций придётся заводить последовательными вызовами `add`.

### При удалении `varnam` мутирует

```sql
update locations set locdelmsk = 0, varnam = varnam||'_'||locid::text
```

После мягкого удаления идентификатор меняется — к нему дописывается `_<locid>`. Значит связь `slug` в NetBox и `varnam` в платформе после удаления расходится. Для сопоставления полагаться следует на `locid`, а не на `varnam`.

### Удаление локации отвязывает оборудование

```sql
update equipments set locid = 0 where locid = any(a_locids_for_del);
```

Оборудование не удаляется, но теряет привязку к месту. Плюс удаляются связи `equip_links` и значения из профилей доступа СКУД (`s_acs_profiles_delete_array_values`). Удаление локации — операция с побочными эффектами, при синхронизации применять осторожно.

### Каскад по дереву

Функция `s_get_locationid()` разворачивает переданный `locid` в массив с потомками — удаление и смена часового пояса применяются ко всей ветке.
