# Файлы импорта в NetBox

Загружать через *Import* в соответствующем разделе NetBox, формат **JSON**.

## Порядок загрузки

1. **Регионы** — заведены вручную 13.08.2026, файла нет. Существующие: Российская Федерация → Автономная Республика Крым → Городской округ Ялта → {г. Ялта, г. Алупка, с. Оползневое, пгт Гаспра, пос. Стройгородок, плато Ай-Петри, Населённый пункт не определён}
2. `01_sites.json` — 5 площадок, ссылаются на регионы **по наименованию**
3. `02_locations_L1…L5.json` — 3 050 локаций, строго по возрастанию уровня. **В репозитории не хранятся**, регенерируются из выгрузки `locations.txt`
4. `03_racks.json` — стойка

## Ограничения формы импорта

Родитель локации и площадка ищутся **по наименованию, глобально по всей базе**. Поэтому в файлах импорта все наименования приведены к глобальной уникальности: `1 этаж` → `1 этаж (Блок А)`, `1 этаж (Энергоцентр)` и т. п. Всего уточнено 1 216 записей из 3 050.

Это обход ограничения формы, а не проектное решение. При работе через REST API родитель передаётся по `id`, и наименования сохраняются как в Р-Платформе.

Файл уровня L4 содержит 2 635 записей — при загрузке включать «Фоновая работа», иначе форма упирается в таймаут.

## Что исключено из выгрузки

- Записи с `locdelmsk = 0` — 347 удалённых
- Семь функциональных групп — по решению уходят в теги, их потомки подняты к корню площадки
- Девять узлов с наименованием «Нулевая» вместе с потомками
