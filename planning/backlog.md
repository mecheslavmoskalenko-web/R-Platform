## 2. Чек-лист доработок производителя — ООО «Рубеж» (R-PLATFORMA)

Источник: сводный документ «На разработку R-Platform», подготовленный по итогам эксплуатации системы.

- [ ] **Телепорт** — реализовать объект «телепорт» на входах/выходах с этажей, на лестницах и длинных переходах между корпусами для быстрой навигации между подложками одним кликом
- [ ] **Отключение неисправных зон** — разработать алгоритм определения аномального количества событий от устройства (например, при поломке датчика Холла точка доступа может генерировать 2–3 события/сек., что переполняет лог и перегружает систему); при обнаружении — автоматически переводить устройство в режим «Out of service» с генерацией инцидента в техподдержку
- [ ] **Дублирование камер и прочих устройств** — реализовать возможность создания визуальных дубликатов объектов (камеры, СКУД), которые физически относятся к нескольким подложкам (например, смежная дверь между корпусами, уличная камера на плане помещения и на GIS-карте), без дублирования в БД
- [ ] **Цвет сектора направления камер** — добавить возможность изменения цвета сектора обзора камеры (плохо видно на светлом фоне), в идеале — вращение иконки целиком (заявка № 73699)
- [ ] **Определение нарушителей периметра на основе весов (костов)** — реализовать взвешенную оценку тревог от разнотипных детекторов периметра для расчёта совокупного уровня угрозы:

  | Стоимость | Тип тревоги |

  | 2 р. | Ложное срабатывание (ИК-датчик движения) |
  | 4 р. | Ложное срабатывание |
  | 7 р. | Приближение к периметру (нейродетектор — распознавание человека) |
  | 10 р. | Пересечение линии/вхождение в зону человеком (нейродетектор) |
  | 12–17 р. | Нарушение периметра |
  | >17 р. | Нарушение периметра — высокий уровень угрозы |

- [ ] **Включение сотрудников в поисковый движок** — добавить сотрудников как искомые сущности в общий поиск системы
- [ ] **Дырки в таймлайне** — индикация наличия/отсутствия записи и наличия/отсутствия тревог на таймлайне
- [ ] **Корректное отображение объектов на карте** — устранить визуальное «слипание» объектов в кучу при плотном расположении

### Замечания по итогам анализа БД `core` (14.08.2026)

- [ ] **СУБД снята с поддержки.** PostgreSQL 11.22, сборка `Debian 1:11.22-astra.se5.1+ci3`. Ветка 11 завершена 09.11.2023, обновления безопасности не выпускаются почти три года. Запросить позицию производителя: план перехода на поддерживаемую версию и сроки
- [ ] **Справочник типов локаций семантически некорректен.** Переиспользован типовой географический справочник с присвоением другого смысла: `locCountry` означает «Уровень 0», `locCity` — «Наименование объекта», `locStreet` — «Блок здания». Вводит в заблуждение при чтении API и интеграции. Проверено: из десяти типов в SQL-коде адресуется только `locBuilding` (5 мест), переименование остальных безопасно
- [ ] **Орфографические ошибки в наименованиях переменных:** `locMovebleProperty` (верно `locMovableProperty`), `locFasad` (верно `locFacade`)
- [ ] **Тип «Движимое имущество» смешивает разные сущности** — стойки и прочее имущество. При интеграции с внешними системами им соответствуют разные модели, различить по типу невозможно
- [ ] **Формат хранения координат не документирован.** `locations.jsoncoords` содержит WGS84 с перестановкой осей по конвенции 3D-движка: `x` — долгота, `z` — широта, `y` всегда 0. Требуется описание в интеграционной документации, включая назначение полей `locked` и `lockedByUser`
- [ ] **Отсутствует контроль целостности дерева локаций.** Поле `parlocid` объявлено как `integer DEFAULT 0 NOT NULL` без внешнего ключа и проверок: любой тип может быть подчинён любому. Следствие в данных — помещения, подчинённые зданию в обход этажа. Требуется контроль допустимых сочетаний «тип родителя — тип потомка»
- [ ] **Мандатное разграничение включено, но не используется.** На уровне БД установлен `MAC CCR ON`, при этом метки всех объектов нулевые, а все 741 таблица создана с `MACS=FALSE`. Требуется позиция производителя: предполагается ли фактическое использование механизма и как это соотносится с требованиями к аттестации объекта
- [ ] **Слабая ссылочная целостность.** 217 внешних ключей на 742 таблицы; связи держатся на соглашении «поле `*id` со значением 0 означает „не задано“». Повышает риск рассогласования данных
- [ ] **Секционирование журнала событий выполнено наследованием.** `eventlog` разбит на 568 суточных секций через `INHERITS`, тогда как PostgreSQL 11 поддерживает декларативное секционирование. Планировщик работает менее эффективно
- [ ] **Уточнить состав штатного API.** Входит ли HTTP-доступ к функциям `s_get_*` / `s_set_*` в стандартную поставку, каков формат ответа `s_set_locations` (объявлена как `RETURNS text`) и возвращается ли присвоенный `locid` при создании локации
